6  Definiciones internas del dominio

Esta es probablemente la sección más importante de la documentación. Define el vocabulario del sistema, los límites conceptuales, y lo que cada término significa exactamente dentro de Thalos.

Los archivos cambian. Los conceptos sobreviven.

6.1 Serial Chain

Una Serial Chain es una secuencia ordenada de segmentos conectados por joints, donde cada elemento depende cinemáticamente del anterior. Es la única topología robótica que Thalos soporta actualmente.

Implementación:

pub struct SerialChain {
    pub segments: Vec<Segment>,
    pub frames: FrameRegistry,
    pub end_effector: FrameId,
}

Lo que NO es: Thalos no soporta robots paralelos, mecanismos cerrados, árboles cinemáticos, ni sistemas híbridos.

6.2 Joint

Elemento que introduce movimiento relativo entre dos segmentos. Cada joint tiene un origen (transform local), un eje de movimiento, y límites físicos.

Dos tipos:

6.2.1 RevoluteJoint

Movimiento rotacional alrededor de un eje. Usa UnitQuaternion::from_axis_angle() para generar la transformación de movimiento.

pub struct RevoluteJoint {
    pub id: JointId,
    pub axis: UnitVector3,     // eje de rotación (normalizado)
    pub limits: JointLimits,   // [min, max] en radianes
    pub origin: Transform3D,   // transform local del joint
}

6.2.2 PrismaticJoint

Movimiento de traslación a lo largo de un eje.

pub struct PrismaticJoint {
    pub id: JointId,
    pub direction: UnitVector3,  // dirección de deslizamiento
    pub distance_limits: JointLimits,  // [min, max] en unidades de distancia
    pub origin: Transform3D,     // transform local del joint
}

6.2.3 JointType (enum unificado)

pub enum JointType {
    Revolute(RevoluteJoint),
    Prismatic(PrismaticJoint),
}

JointType delega a la variante concreta para motion(q), origin(), axis(), axis_world(transform), y kind().

6.3 Link

Elemento rígido entre dos joints. Representa la geometría física del eslabón: una transformación fija desde el child frame del joint anterior hasta el origen del siguiente.

pub struct Link {
    pub id: LinkId,
    pub transform: Transform3D,  // transform rígido del eslabón
}

Si el link es recto y de longitud L a lo largo del eje X, su transform sería Transform3D::from_translation(Vector3::new(L, 0.0, 0.0)).

6.4 Segment

Unidad estructural que agrupa un joint y un link, conectando dos frames (parent y child). Es la abstracción de “eslabón + articulación” que compone la cadena.

pub struct Segment {
    pub parent: FrameId,      // frame del segmento anterior
    pub child: FrameId,       // frame de este segmento
    pub joint: JointType,     // articulación (revolute | prismatic)
    pub link: Link,           // eslabón rígido
}

La razón por la que Segment existe aparte de Link:

Concepto Representa
Joint El movimiento relativo
Link La geometría rígida
Segment La unidad completa: joint + link + conexión entre frames

Un Segment no es “un link con un joint adentro”. Es la relación completa entre dos frames de la cadena.

6.5 Sistema espacial

El sistema espacial de Thalos es, conceptualmente, una de las piezas más importantes. Es el puente entre el dominio robótico (estructuras de robot) y el dominio cinemático (FK, jacobianos). También es el modelo que la visualización proyecta al mundo exterior.

Lo que hace especial a este diseño es que trata los frames como entidades explícitas con identidad propia, no como strings o índices implícitos.

6.5.1 Frame

Un Frame es un sistema de referencia espacial. Es la unidad fundamental de la representación espacial en Thalos.

pub enum FrameId {
    World,         // frame raíz global (siempre existe)
    Id(u64),       // frame numerado
}

pub struct Frame {
    id: FrameId,
    name: String,
}

FrameId::World es el frame canónico — toda pose global se expresa relativa a World. Los FrameId::Id(n) se crean automáticamente por el FrameRegistry o pueden asignarse manualmente para casos especiales.

6.5.2 FrameRegistry

Registro central que mapea FrameIds a Frames. Es el índice de todos los frames de una cadena.

pub struct FrameRegistry {
    frames: HashMap<FrameId, Frame>,
    next_id: u64,
}

Operaciones: - create(name) → crea un nuevo Frame con ID auto-incremental, lo registra, y devuelve el FrameId - register(frame) → registra un frame existente (útil para IDs predefinidos como World) - get(id) → lookup por ID - contains(id) → verifica existencia

La SerialChain contiene un FrameRegistry completo. Cada Segment referencia frames por su FrameId, no por nombre. Esto significa que:

  • No puede haber frames huérfanos (el builder valida)
  • No puede haber colisiones de nombres (los IDs son numéricos)
  • El registro es la fuente de verdad de qué frames existen

6.5.3 Pose

Una Pose es la relación espacial entre dos frames: la transformación rígida que lleva del frame reference al frame target.

pub struct Pose {
    reference: FrameId,
    target: FrameId,
    transform: Transform3D,   // T_reference→target
}

Semántica: - Pose::new(world, child, t) → “el frame child está en t relativo al mundo” - is_global() → true si reference == FrameId::World - transform() devuelve la Transform3D que mapea puntos de reference a target

El FKResult contiene un HashMap<FrameId, Pose> con la pose global de cada frame de la cadena para una configuración q dada.

6.5.4 FrameGraph

Grafo de relaciones espaciales (esqueleto inicial). Actualmente declarado pero no implementado. Su propósito futuro será permitir:

  • Navegación entre frames parent/child
  • Composición de transformaciones a lo largo del grafo
  • Detección de ciclos en el grafo de referencia
  • Consultas del tipo “dame la pose del frame A relativa al frame B”

6.5.5 ¿Cómo conecta el sistema espacial con el resto?

El sistema espacial es la columna vertebral que permite que el análisis cinemático se traduzca a representación visual sin acoplamiento.

6.6 Model

Configuración estructural concreta de un robot. Combina un modelo genérico (enum RobotModel) con parámetros específicos (enum RobotSpec).

pub enum RobotModel {
    Planar2R,
    Planar3R,
    SingleRevolute,
    Scara,
    Manipulator3DOF,
    Manipulator6DOF,
    CylindricalRPP,
    SphericalPolarRRP,
}

pub enum RobotSpec {
    Planar2R(Planar2RSpec),
    Planar3R(Planar3RSpec),
    SingleRevolute(SingleRevoluteSpec),
    Scara(ScaraSpec),
    Manipulator3DOF(Manipulator3DOFSpec),
    Manipulator6DOF(Manipulator6DOFSpec),
    CylindricalRPP(CylindricalRPPSpec),
    SphericalPolarRRP(SphericalPolarRRPSpec),
}

RobotRegistry::create(model, spec) valida que model y spec coincidan y construye la SerialChain correspondiente usando la fábrica adecuada.

let robot = RobotRegistry::create(RobotModel::Planar2R, RobotSpec::Planar2R { l1: 1.0, l2: 1.0 })?;

6.7 Inverse Kinematics (IK)

Thalos implementa dos solvers de cinemática inversa en thalos-core::kinematics::inverse:

6.7.1 Damped Least Squares (DLS)

Solver iterativo basado en el jacobiano geodésico con damping. Robusto cerca de singularidades. Es el solver por defecto para MoveToPosition y MoveToPose.

pub struct DampedLeastSquaresSolver {
    fk: ForwardKinematics,
    frame: FrameId,
    max_iters: usize,
    tolerance: f64,
    lambda: f64,       // damping factor
}

impl IKSolver for DampedLeastSquaresSolver {
    fn solve(&self, q0: &[f64], goal: IKGoal) -> IKResult;
}

6.7.2 Jacobian Transpose (JT)

Solver basado en la transpuesta del jacobiano. Menos preciso que DLS pero más rápido computacionalmente.

6.7.3 IKGoal

pub enum IKGoal {
    Position(Vector3),
    Pose(Pose),
}

6.7.4 IKResult

pub struct IKResult {
    pub q: Vec<f64>,           // solución articular
    pub final_error: f64,      // error residual
    pub iterations: usize,     // iteraciones usadas
    pub status: IKStatus,      // Converged, MaxIterationsReached, Singularity
}

6.8 Flange y TCP (Tool Center Point)

Thalos separa el concepto de “end effector” en dos, siguiendo el estándar de la robótica industrial (ver ADR-0002):

6.8.1 Flange

El último frame mecánico del robot (chain.end_effector). Es inmutable durante la vida del robot. Es el punto donde se monta la herramienta.

6.8.2 TCP activo

Un frame opcional (SceneRuntime::active_tcp: Option<ToolFrame>) que representa la herramienta activa. Puede cambiar en runtime sin reconstruir la cadena cinemática.

pub struct ToolFrame {
    pub base_frame: FrameId,     // Frame base (ej: flange, tool0)
    pub transform: Transform3D,  // Offset desde base_frame
}

6.8.3 Invariantes del runtime

  1. Si active_tcp es Some, entonces base_frame existe en la cadena cinemática.
  2. Al cambiar de robot (LoadRobot, LoadUrdfRobot), active_tcp se limpia a None.
  3. La validación del frame ocurre en SceneRuntime::select_tool_frame().

6.8.4 Impacto en el sistema

Cuando active_tcp está presente, todos los análisis operacionales lo usan: workspace, jacobiano, singularidad, manipulabilidad, planning, IK. Cuando es None, se usa el flange (comportamiento anterior).

Término Definición

Link Elemento rígido entre joints
Segment Unidad estructural: joint + link + conexión entre frames
Pose Posición + orientación de un frame relativo a otro
Frame Sistema de referencia espacial
FrameRegistry Registro central de frames con auto-incremento
FrameGraph Grafo de relaciones entre frames (esqueleto)
Model Configuración paramétrica de un robot concreto
FK Cálculo de poses dado un vector de configuración q
Jacobian Matriz que relaciona velocidades de joints con velocidades del end-effector
IK (Inverse Kinematics) Cálculo de configuración articular q para una pose deseada
