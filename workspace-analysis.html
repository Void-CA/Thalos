5  Análisis de Workspace

5.1 Introducción

El análisis de workspace es una técnica fundamental en robótica que permite caracterizar el espacio de trabajo de un manipulador: el conjunto de posiciones (y opcionalmente orientaciones) que el end-effector puede alcanzar dadas las limitaciones físicas de sus articulaciones.

Thalos implementa análisis de workspace mediante muestreo Monte Carlo: en lugar de calcular analíticamente la frontera del workspace (complejo y dependiente de la geometría del robot), se muestrean configuraciones articulares aleatorias uniformes, se evalúa la cinemática directa (FK) para cada una, y se construye un dataset de posiciones alcanzables.

Este enfoque tiene varias ventajas:

  • Robot-agnóstico: funciona para cualquier SerialChain
  • Paralelizable: cada muestra es independiente (embarazosamente paralelo)
  • Aproximación probabilística: la calidad mejora con más muestras
  • Base para análisis avanzados: singularidades, manipulabilidad, validación de trayectorias

5.2 Conceptos fundamentales

5.2.1 WorkspaceSample

La unidad atómica del análisis: una configuración articular q y la posición 3D del end-effector que produce.

pub struct WorkspaceSample {
    pub q: Vec<f64>,          // configuración articular
    pub position: Vector3,    // posición del end-effector
}

Invariante: position == FK(chain, q).ee_position() (garantizado por el sampler).

5.2.2 BoundingBox

Caja alineada a ejes (AABB) que envuelve todas las posiciones muestreadas. Es la aproximación más simple del workspace: un ortoedro definido por sus esquinas mínima y máxima.

pub struct BoundingBox {
    pub min: Vector3,
    pub max: Vector3,
}

5.2.3 WorkspaceMetrics

Métricas derivadas del conjunto de posiciones. Calculadas en una pasada O(n) durante la construcción del Workspace.

pub struct WorkspaceMetrics {
    pub bounding_volume: f64, // volumen del AABB (no del workspace real)
    pub max_reach: f64,       // distancia máxima al origen
    pub min_reach: f64,       // distancia mínima al origen
    pub centroid: Vector3,    // media aritmética de posiciones
    pub sample_count: usize,  // número de muestras
}

⚠️ bounding_volume ≠ volumen del workspace real. El volumen del AABB sobreestima drásticamente el workspace (especialmente para robots con huecos internos). Métricas de forma real (convex hull, voxelización) están planificadas para fases futuras.

5.2.4 WorkspaceConfig

Parámetros de configuración para el muestreo y las consultas de alcanzabilidad.

pub struct WorkspaceConfig {
    pub samples: usize,   // > 0, número de configuraciones a muestrear
    pub seed: u64,        // semilla determinista (StdRng::seed_from_u64)
    pub tolerance: f64,   // >= 0, tolerancia en metros para reachability
}

Valores por defecto: samples = 10_000, seed = 0xDEAD_BEEF, tolerance = 1e-3.

5.2.5 Workspace

Dataset inmutable que contiene las muestras, bounds y métricas derivadas.

pub struct Workspace {
    samples: Vec<WorkspaceSample>,  // privado
    bounds: BoundingBox,            // privado
    metrics: WorkspaceMetrics,      // privado
}

Métodos públicos:

  • from_samples(samples) — constructor único, O(n) secuencial, rechaza vacío
  • samples() -> &[WorkspaceSample] — vista de las muestras
  • bounds() -> &BoundingBox — AABB derivado
  • metrics() -> &WorkspaceMetrics — métricas derivadas
  • is_reachable(point, tolerance) -> Result<Reachability, WorkspaceError> — consulta de alcanzabilidad

5.3 Muestreo Monte Carlo

El WorkspaceSampler implementa el algoritmo de muestreo:

  1. Recibe un SerialChain + WorkspaceConfig + RNG
  2. Para cada muestra:
    1. Genera una configuración articular aleatoria uniforme dentro de los límites de cada joint
    2. Evalúa FK con ForwardKinematics::evaluate(q)
    3. Extrae ee_position() del resultado
  3. Construye un Workspace con todas las muestras
pub struct WorkspaceSampler;

impl WorkspaceSampler {
    pub fn sample<R: Rng + SeedableRng>(
        &self,
        chain: &SerialChain,
        config: WorkspaceConfig,
        rng: &mut R,
    ) -> Result<Workspace, WorkspaceError>;
}

El RNG se inyecta externamente, lo que permite:

  • Tests deterministas (R1): fijando la semilla, el mismo chain + config produce siempre el mismo Workspace
  • Producción: WorkspaceService::sample() usa StdRng::seed_from_u64(seed) para crear un RNG determinista a partir de la semilla

La función que genera un joint value aleatorio es:

q_j ~ U(limit_j.min, limit_j.max)

donde limit_j son los límites físicos del j-ésimo joint. Cada joint se muestrea independientemente.

5.3.1 Invariantes clave

ID Invariante ¿Dónde se valida?
FK position == FK(chain, q).ee_position() Sampler (garantizado)
R1 Mismo chain + config + seed → mismo Workspace Tests de integración
R2 sample_count == config.samples Workspace::from_samples()
R3 samples.q[i].len() == n_dof Por construcción
R8 Rechaza samples = 0 WorkspaceError::InvalidSampleCount

5.4 Consulta de alcanzabilidad

La consulta de alcanzabilidad determina si un punto p en el espacio 3D es alcanzable por el end-effector, dentro de una tolerancia dada.

pub enum Reachability {
    /// El punto está dentro de la tolerancia de al menos una muestra.
    Reachable,
    /// El punto está más lejos que la tolerancia de toda muestra.
    OutOfWorkspace {
        nearest_distance: f64,  // distancia mínima a cualquier muestra
    },
}

5.4.1 Algoritmo (Workspace::is_reachable)

  1. Validación de entrada:
    • tolerance >= 0 y no NaN → InvalidTolerance si falla
    • point sin NaN ni Infinity → InvalidPoint si falla
  2. Búsqueda lineal O(n) sobre todas las posiciones muestreadas
  3. Si min_distance <= tolerance → Reachable
  4. Si no → OutOfWorkspace { nearest_distance: min_distance }

La búsqueda lineal es deliberada (D1): para datasets de ~10K-100K muestras es suficiente. Optimizaciones espaciales (KD-tree, octree) están planificadas para cuando el tamaño del workspace lo justifique.

5.5.1 thalos-core

Responsabilidad: tipos de dominio y algoritmo de muestreo. No sabe de HTTP, visualización ni runtime.

Crate puro: depende solo de nalgebra para tipos matemáticos, thiserror para errores, y rand para el sampler.

5.5.2 thalos-runtime

WorkspaceService — servicio stateless (sin estado mutable). Toma un RobotModel y config, construye la SerialChain via RobotRegistry, crea un StdRng con la semilla, y delega en WorkspaceSampler.

Todas las funciones son pub fn estáticas — no requieren instancia:

impl WorkspaceService {
    pub fn sample(model: RobotModel, config: WorkspaceConfig)
        -> Result<Arc<Workspace>, RuntimeError>;

    pub fn query(workspace: &Workspace, point: &Vector3, tolerance: f64)
        -> Result<Reachability, WorkspaceError>;
}

Devuelve Arc<Workspace> para permitir compartir el dataset entre hilos sin copia (D10). Un futuro cacheo con HashMap<WorkspaceKey, Arc<Workspace>> es trivial de agregar.

5.5.3 thalos-api

Dos endpoints HTTP, ambos POST:

5.5.3.1 POST /api/v1/workspace/sample

// Request
{
  "robot_id": "scara",
  "samples": 50000,
  "seed": 42,
  "tolerance": 0.001,
  "include_samples": false
}

// Response (include_samples: false)
{
  "metrics": {
    "bounding_volume": 8.234,
    "max_reach": 2.121,
    "min_reach": 0.453,
    "centroid": { "x": 0.0, "y": 0.8, "z": -0.2 },
    "sample_count": 50000
  },
  "bounds": {
    "min": { "x": -1.5, "y": -1.5, "z": -0.5 },
    "max": { "x":  1.5, "y":  1.5, "z":  0.5 }
  }
}

5.5.3.2 POST /api/v1/workspace/reachability

Autocontenido: muestrea un workspace SCARA con parámetros por defecto (10K muestras, tolerancia 1e-3) y ejecuta la consulta:

// Request
{
  "point": { "x": 0.5, "y": 0.5, "z": 0.0 },
  "tolerance": 0.01
}

// Response
{
  "reachable": true,
  "nearest_distance": 0.0023
}

5.5.4 thalos-visual

WorkspaceVisual — representación visual completa del workspace:

  • BoundsWireframe: AABB como 12 aristas (wireframe) definido por min/max
  • SamplePointCloud: nube de puntos 3D (todas las posiciones muestreadas)
  • robot_overlay: Option<VisualScene>: escena del robot superpuesta (opcional, para contexto visual)
pub struct WorkspaceVisual {
    pub bounds_wireframe: BoundsWireframe,
    pub samples_points: SamplePointCloud,
    pub robot_overlay: Option<VisualScene>,
}
pub struct BoundsWireframe {
    pub min: [f64; 3],
    pub max: [f64; 3],
}
// Provee edges() -> 12 segmentos [(start, end); 12]

pub struct SamplePointCloud {
    pub points: Vec<[f64; 3]>,
    pub count: usize,
}

5.5.5 Frontend (Angular)

Dos componentes standalone en la feature workspace:

5.5.5.1 WorkspacePanel

Panel lateral con:

  • Formulario: selector de robot, número de muestras, semilla, tolerancia, toggle de incluir muestras en respuesta
  • Métricas: muestra bounding_volume, max_reach, min_reach, centroid
  • Consulta de alcanzabilidad: inputs X/Y/Z + tolerance, botón “Check”, y resultado (Reachable / OutOfWorkspace con distancia)

Estado reactivo via WorkspaceStore (Angular Signals):

interface WorkspaceState {
  loading: boolean;
  error: string | null;
  metrics: WorkspaceMetrics | null;
  bounds: BoundingBox | null;
  reachability: ReachabilityResult | null;
}

5.5.5.2 WorkspaceRenderer

Canvas Three.js que renderiza:

  • AABB wireframe (12 aristas) del BoundsWireframe
  • (Futuro) nube de puntos 3D del SamplePointCloud

Usa effect() para reaccionar a cambios en el store, renderizando sobre un canvas standalone sin depender del ThreeRendererService del scene viewer.

5.7 Tests

El workspace analysis tiene 71 tests unitarios + 7 tests de visualización, distribuidos así:

Capa Tests Cobertura
Core (dominio) 44 Workspace, Sampler, Reachability, BoundingBox, Metrics
Runtime 11 WorkspaceService::sample, WorkspaceService::query
API (integración) 5 Endpoints HTTP, DTO conversion, error mapping
Visual 7 (2 snapshot) WorkspaceVisual, BoundsWireframe::edges, SamplePointCloud

5.7.1 Invariantes bajo test

  • R1 (determinismo): mismo seed → mismo workspace
  • R2 (conteo): samples.len() == config.samples
  • R3 (dimensionalidad): cada q tiene n_dof elementos
  • R4 (reachability): punto conocido → Reachable; punto lejano → OutOfWorkspace
  • R5 (tolerance): tolerance = 0 → solo puntos exactos
  • R6 (punto inválido): NaN o Infinity → InvalidPoint
  • R7 (parámetros inválidos): samples = 0 → error; tolerance < 0 → error
  • R8 (jacobiano): FK produce ee_position para joint values aleatorios
  • D4 (RNG): StdRng::seed_from_u64 para determinismo
  • D1 (búsqueda lineal): implementación O(n) actual, optimización futura
